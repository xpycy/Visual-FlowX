# 流程&应用
1 Data Define ，基础数据建模，定义数据结构及默认值、约束、key、index、外键引用约束等
  应用类案例 drawDB， https://github.com/drawdb-io/drawdb

2 流程相关，纯流转
	2.1 xml,json格式的协议定义
	2.2 flow层的基础定义，走规范协议，借用BPMN,只需要摘抄部分图元概念、汇图、落盘为json或xml即可
	2.3 flow运行时逻辑，针对流程自身的，如状态、启停、有效性、唯一性等
	2.4 flow运行管理器，定义、校验、发布计划、运行监控、数据流&健康状态、生命周期管理等
	2.5 flow之间的关联，转向、通知、跳转&调用，多流程并行或串行等编排
	2.6 flow的图形化呈现，运行时动态数据流向的效果化、流向指向标记，单次会话、生命周期性的日志追踪、呈现	
	
3 流程&数据 外挂应用层
    3.1 flow的应用模板定义管理，即在基础流转上，做叠放绑定应用	
	3.2 flow层之上的交互层协议定义，形成数据交互关系逻辑，流经flow的主数据对象、环境数据，预绑定、预提取、设定，形成flow入口点数据环境预加载		  
	3.3 flow节点绑定单多个逻辑卡片，在各节点挂载环境信息&基础设施webapi、数据对象接口等，即预制各flow节点内活动脚本集，仅做绑定、数据判断、功能点调用、串联
	3.4 拆分信息、合并、拼装组合数据对象，投放或转入不同流程节点，做流程节点新的数据集环境管控，或数据流向
	3.5 居于单、多个流程节点，做前后置预环境运行信息校验判断、运算、流逻辑等编排，如：生产工艺不同工序段处理判断、分析、过滤等，形成提前抽象流逻辑；（动态属性、预判、容错性、分支流向）
	3.6 外挂应用层形成二次应用协议json格式存储，导入、导出、卡片化管理
	3.7 手动拖放预测数据集，实时流程数据流动呈现

4 配置文档的多样本，训练后对话生成
    4.1 生成常规应用配置模板，做QLoRA训练及对话
	    对话后大模型只是生成json片断，平台负责加载、解析、运行
	4.2 居于行业应用的训练集+Agent对话生成配置，图形化交互

5 解决方案
    5.1 前述的部分为原始起点，最终形成的多数据集、流程、模板、参数（配方），最终打包绑定（流程、配方）形成应用套餐
	5.2 发布应用套餐为运行状态后，仅能对运行中的流程做实时运维、动态参数监控、授权微调
	5.3 每一个运行中流转图形化呈现，监控实时数据流、性能、预警、分发的周边信息、日志等
	5.4 对运行的周边信息、采集回路、现场反馈信息、质量检测数据，做二次回路流程叠放管控编排；（也是流程的一种，前置或后置预定义）

# 示例： test specification: 期望反馈、校验等
` 描述
1）归纳为对数据属性、值 的约束或过滤
2）参与计算的数据，可能是宿主数据对象自身、属性项、值，可能是调用者运行值、即时值，或平均值等
3）可能是采集的环境值；或调用第三方webapi返回等一系列逻辑组合
4）归属为：属于短程、单一功能逻辑
` 挂载
1) 部分可拖放进入实时数据流"网片栅检逻辑"实时触发、推送，部分挂载至数据类型固有校检项行为
2) 归属为基础约束一类，独立、专项定义、管理，可控挂载，非硬编码嵌入



`实时反馈部分，绑定数据、环境信息那里，接入第三方基础设施、数据采集信息、redis等实时信息，
1) 流程投放到在线服务中，引入实时环境信息，这样做整场的交互、反馈
2) 部分流程节点信息，做数据推送第三方，或接受来自第三方的录入等，正反向交互
3）推向第三方，如：用户录入过站信息、用料等，属于推送、转存形式，如：推至kafka，由第三方界面交互呈现、录入
   将界面交互与流程分离
4）数据流转会话时效性控制补充：单个数据对象的单次启动，定义为一次会话，可编排做单节点、整场时效周期、回环次数等管控，细节不在此陈述
   包括推送、预警等


# 逻辑解耦
1）针对常规的mes或mis类型的长流程、复杂数据交互，做分层定义
2）总体上做流程编排，单点上对接数据绑定判断、方法、接口挂接，形成基础编排式管理
3）数据点层面，做针对性逻辑约束、第三方调用预定义形式化，可插拔式代入不同场景
4）预定义、实时&运行时、会话隔离、全场环境实时流（单线&整场）交互
5）居点单、多流程节点的抽象逻辑定义、数据过滤、约束、查询等，应用维度编程
6）人工、预编排机制，运行时动态震荡平衡，做后期运维层逻辑，与开发隔离
